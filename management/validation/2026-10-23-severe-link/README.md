# 高频断流与丢包优化实测（2026-10-23）

这次改善结果交付和握手故障恢复，保留低占用、默认静默和离线退避。当前版本在高延迟、限速、频繁断流的 H1/H2 测试中均完成了全部三次交付；叠加真实 5% 丢包后仍存在明显尾延迟，不能宣称所有场景通过。

## 最终改动

1. 结果上传首次仍使用原来的最大 64 KiB 分块。数据请求失败后，先探测 Controller 的持久偏移；只有确认没有进度，才将分块上限降为失败正文大小的四分之一，最低 4 KiB。当前结果保持小块，下一个结果重新使用 64 KiB。单纯探测失败、丢失 ACK 但数据已提交，都不会盲目缩块。
2. 探测确认已落盘进度时，也重置上传退避。这等价于补收了丢失的 ACK，避免传输实际在前进，等待却不断翻倍。真正无进度或离线时保留原有抖动、指数退避及 30 秒基数上限；未添加高频心跳或并发上传。
3. `CHISEL_SSH_TIMEOUT` 现在覆盖 SSH 协商和配置 ACK 等待。此前使用 `ssh.NewClientConn`，并不会自动应用 `ClientConfig.Timeout`。默认仍为 30 秒；握手成功后停止定时器，已建立隧道不受它影响。取消仍会关闭连接。

数据完整性、SHA-256、磁盘结果身份核验、stdout/stderr 边界、落盘确认后清理及任务不重复执行仍由原有机制和回归测试保证。生产修改见 [optimization.patch](optimization.patch)，仅包含本轮两个生产文件的差异。

## 共同测量条件

Linux amd64，Intel Xeon CPU Max 9470C。修改前基线已经包含上一轮低占用优化。两侧 Node 均为 Go 1.23.12、`-trimpath`、非 race、`GOMAXPROCS=2`；使用同一个 Go 1.27.0 夹具二进制，GOGC/GOMEMLIMIT 保持默认，不强制 GC。

一次任务产生 **32,768 B stdout + 15 B stderr**。开始计时前已完成任务执行，并停在第一次上传探测；计时包含随后上传、退避、重连，排除初始注册与命令下发。数据全部完成后核对准确字节，另用执行标记验证任务恰好运行一次。Controller 的观察请求在进程内进行，不争抢被测链路。

- 每方向增加 300 ms 延迟，即约 600 ms 额外 RTT；每条连接、每方向限制 8 KiB/s。
- 每 4 秒关闭全部代理连接，离线 500 ms；不是只暂停应用读取。
- 代理队列固定为两个 2 KiB 块，另有生产者/消费者缓冲区；没有无界排队。
- 丢包组额外在独立网络命名空间的 loopback 上施加 netem：5% 丢包、2 ms 延迟、4096 kbit/s、seed 7。实际 TCP 重传由内核处理。宿主网卡未修改。
- Node 使用 `GODEBUG=randautoseed=0` 固定初始随机种子，但线程调度、随机数调用顺序、TCP 重传仍会变化。各 profile 可并行执行；原版基线复用于不同候选。最终 H1 基线早于最终候选，H2 第 2、3 轮为先 before 后 after。不是完全交替或统计置信实验。

## 交付结果

`completed` 与资源/完整性 `passed` 是分开的字段。原版允许在预算耗尽时保留未完成记录；候选开启 `TACK_SEVERE_REQUIRE_COMPLETE=1`。未完成不是成功，也不是零耗时。

| 场景 | 原版 | 最终版本 |
| --- | --- | --- |
| H1，高延迟 + 限速 + 断流，75 秒预算，各 3 次 | 0/3 完成，全部 0 B 持久进度 | **3/3 完成，中位 23.850 s，范围 23.848–30.375 s** |
| H2，同条件，各 3 次 | 0/3 完成，全部 0 B 持久进度 | **3/3 完成，中位 47.697 s，范围 47.194–47.949 s** |
| H1，再加 5% 丢包，120 秒预算，各 1 次 | 未完成，0 B 进度 | **51.973 s 完成** |
| H2，再加 5% 丢包，120 秒预算，各 1 次 | 未完成，0 B 进度 | **未完成，32,771 / 32,783 B 持久进度（99.963%）** |

H2 的最后一项是明确的完成门槛失败，完整原始报告保留为 `process/loss-h2/after-1.json`，`passed=false`。局部 `.part` 文件大小仅表明持久进度，不能替代完整结果校验。

随后单独进行一组 **180 秒预算的 H2 丢包诊断**：原版到 180.186 秒仍为 0 B，最终版本这次在 **51.973 秒**完成。此次开始时序不同，并非延长前一次运行；它反映同配置的显著时序波动，不能拿它替换前面的 120 秒失败样本，或宣称仅延长预算就必然恢复。诊断单独保存在 `diagnostic/loss-h2-180/`。

## 握手与回归

静默 SSH 夹具配置 100 ms 握手超时，500 ms 外部 watchdog，`5 次 × 3 组`。原版每次都靠 watchdog 才退出，中位 **500.529 ms/op，15/15 次触发 watchdog**；最终版本中位 **100.935 ms/op，0/15 次触发 watchdog**。这是故障等待有界化，不是五倍传输性能。默认产品超时仍为 30 秒。

- 根模块 Go 1.27.0 全量 race/vet 通过，包括 SSH banner、配置 ACK、取消、重连及建立成功后超时定时器不误关连接。
- Node/runner Go 1.23.12 全量 race/vet 通过，包括无进度缩块、丢 ACK 保持块大小、4 KiB 下限、磁盘内容与输出边界、探测补确认后重置退避。
- 管理集成模块 Go 1.27.0 全量 race/vet 通过；低占用 H1/H2 独立进程门限通过。
- 迁移覆盖检查、覆盖检查反例、`git diff --check` 通过。
- **H2 + 5% 丢包的主实验完成门槛未通过**；上面的全量回归默认不运行这个显式开启的资格测试。

## 未采用的实验

保留在 `exploratory/`，不混入最终统计：

- 最初 6 秒断流间隔的原版可在 6.029 秒完成，因此改用更严格的 4 秒间隔进行共同对照。
- 每次仅缩为一半的候选在 H1 的 75 秒内仍无落盘进度。
- 四分之一缩块但不重置探测确认后的退避：H2 75 秒/120 秒丢包窗口都停在 8,195 B。最终版本修复该退避问题。
- 将下限继续降到 1 KiB：H1 无额外丢包耗时 35.889 秒、丢包耗时 59.758 秒；H2 分别仅推进 2,048 B / 22,531 B。更多小请求和确认未能改善本次测试，已撤回。最终生产文件重新构建后，与接受的 4 KiB 候选二进制 SHA-256 完全一致。
