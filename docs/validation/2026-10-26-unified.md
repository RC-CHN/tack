# 单进程 Node 与 Chisel 验证 — 2026-10-26

本轮将 Chisel 客户端库编进根模块 `cmd/tack-node`，与管理执行器共用一个前台进程。测试版本为 `0.0.0-ci`，基于 `b552402` 后的未提交工作区；没有创建标签、推送或发布。以下结果为本地 Linux amd64 验证，不能代替 Windows/嵌入式真机测试。

## 最终产物

| 项目 | 结果 |
| --- | --- |
| Go / Garble / UPX | 1.26.3 / v0.17.0 / 5.0.2 |
| 保护 | 整体混淆并成功加壳，无降级；CGO 关闭，无 race 插桩 |
| 加壳前二进制 | 9,388,158 B |
| 最终 Node 二进制 | 3,367,156 B，约 3.21 MiB |
| SHA-256 | `b6dc6c0e4cd10e19d1779bfbc96b1295cea48abcef4a052cf2b6e5e8110851c6` |
| 完整性 | UPX 自检、逐字节解压回验、版本执行、归档校验通过 |
| 构建能力记录 | `management`、`embedded-chisel` |

`scripts/smoke-unified.py` 对从归档解出的最终文件进行双功能验证：

- 同一个 Node PID 完成两次 256 KiB TLS 隧道回显和两项非交互 Shell 任务。
- 停止隧道服务端期间，第二项管理任务仍正常完成；重启隧道服务端后自动恢复，Node 未重启。
- 任务完成后没有残留客户端子进程；SIGTERM 正常退出，原监听端口可重新绑定。
- Node 默认诊断输出为 0 B。
- 此短时双功能场景观察到 Node 峰值 RSS 15,344 KiB（约 14.98 MiB）；不包括托管端与任务子进程，不是压力上限。

## 资源与回归

同一最终文件通过既有 `TestNodeLowFootprint` 的 32 MiB RSS 门禁。此项测试未配置隧道，使用管理 HTTP/1、每任务 2 MiB 输出和每阶段 5 秒观测，覆盖空闲、上传阻塞、断线与恢复。

| 阶段 | 观察到的最大 RSS |
| --- | --- |
| 空闲 | 14,128 KiB |
| 上传阻塞 | 20,124 KiB |
| 断线 | 20,152 KiB |
| 恢复后空闲 | 17,040 KiB |

该资源场景恢复并收齐三项结果耗时约 8.42 秒，退出约 6.56 毫秒。空闲与恢复空闲窗口内 CPU tick 和写盘计数均无增量；短窗口不代表长期零占用。没有将历史管理专用 Node 数据当作合并版结论。

通过的本地检查：

- 根模块全部 race 测试与 vet；包括现有 Chisel 端到端测试和新内嵌运行测试。
- protocol、control、node、integration 四个管理模块全部 race 测试与 vet。
- Go 1.23.12 下新增管理执行器生命周期回归：服务失败返回错误并释放锁、重复 Node 不启动服务、管理专用构建拒绝隧道配置。
- Python 8 项既有构建/资格测试、工作流 actionlint、部署 skill 校验。
- 合并版交叉编译：Windows amd64/arm64，Linux 386、ARMv5、MIPSLE softfloat。未执行这些目标的二进制。

新测试还验证：控制端不可达时，内嵌隧道仍可传输；Node 取消后释放隧道监听器；Chisel 派生日志遵循统一日志目的地。

## 限制与原始证据

本轮初始验证时 CentOS 6 的旧内核目标尚未完成；随后增加的 Legacy 统一客户端与真实旧内核证据见[兼容验证记录](2026-10-26-legacy.md)。本页数值仍仅描述上面的 Modern 产物。此次没有运行真实 Windows/ARM/MIPS/NAS、长时间双功能压力测试或发布托管 CI；动态下发隧道配置也未实现。
