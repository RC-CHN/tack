# Hosted control plane

Use a modern operator-controlled host. From v0.1.2, the release `tack-control` contains both the Controller and Chisel server. It has `-listen` for Node HTTPS, `-admin-listen` for loopback-only administration, and an optional `tunnel.listen` for the embedded tunnel server. The listeners and credentials remain separate. If terminating TLS at a proxy, expose only the intended customer-facing listeners; never publish the private administrator port.

Choose the server's run account, configuration/state directories, TLS termination, DNS and firewall configuration for the actual hosting environment. Operator credentials and signing keys remain on this side. Run `tack` on the control host or through explicitly authorized administrator access.

Customer nodes are untrusted even after authentication. Each node credential authorizes only that node's synchronization. A captured node credential must not grant a shell on the hosted server, administrator API access, another customer's identity, arbitrary HTTP proxying or access to controller infrastructure through a Chisel tunnel. The embedded relay needs its own restricted credentials, destination ACLs and network boundary. The unified Node holds a separate node-specific Chisel credential; management credentials do not authorize tunnels. Revocation must cover both authorization stores independently. A unified process shares its operating-system identity and network access; separate listeners are not process isolation.

For a new installation, follow [the unified hosted server guide](../../../docs/unified-control.md) to create a persistent server key and restricted account file, add the Controller `tunnel` object and obtain its fingerprint. Install one Controller startup definition. Supply Nodes only their own tunnel account and the public fingerprint, never the server key or account database. The three release components are `tack-control`, `tack-node` and the operator CLI `tack`; no standalone `chisel` download is needed.

For an existing separate relay, preserve its server key, account/ACL file, TLS identity and advertised address. Check the equivalent options before switching listeners, stop the old relay before binding its port, then start the unified Controller and verify a targeted command plus an actual authorized tunnel transfer. Do not regenerate the server key during migration. Old configuration without `tunnel` keeps management-only operation, so a separately hosted relay can remain until deliberately migrated. Existing reverse/SOCKS policy must be selected explicitly in the new configuration.

The first stage uses static random node tokens and process-local route isolation. Production rollout additionally requires the certificate lifecycle, customer authorization, rate limits and service/network separation in the design. A compromised node can falsify its own results. Do not use self-reported hostnames, paths, labels or capabilities as privileged deployment instructions.

Never promise that software-only local encryption hides a credential from the Node's own account or root. Use protected files/ACLs against lower-privilege access. Hardware-backed non-exportable keys are an optional future identity provider; a compromised original device may still invoke them. Native CentOS 6, MIPS and minimal NAS targets cannot be assumed to have TPM support.

Record how to add and revoke nodes. In the current implementation `tack provision` updates controller configuration, and the Controller must restart to load changes. Remove a node entry and restart to revoke it. Preserve the task state file. A unified Controller restart also disconnects all hosted tunnels until their clients reconnect; plan that shared interruption. Removing an account from the tunnel authorization file prevents subsequent authentication but is not a guarantee that an established session immediately closes. Revocation prevents further synchronization; it cannot remotely stop an already disconnected local process.

For automation operators, use scoped credentials through the private listener; `operator-set` and `operator-revoke` take effect for new requests without a Controller restart. Preserve stable operator IDs across token rotation and back up the matching `.operators.json` store with task state. See [task operations](../../../docs/task-operations.md) for scope, retry and recovery semantics. Node credential provisioning/revocation still uses the restart workflow above.
